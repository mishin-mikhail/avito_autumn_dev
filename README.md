# Avito: кандидатогенерация для поиска услуг (Recall@50)

Для каждого поискового запроса решение отбирает до 50 объявлений из корпуса
(189 212 объявлений, 2 452 запроса). Метрика — Recall@50.

> Статус: **бейзлайн**. Разделы «Результаты» и «Найденные ошибки» заполняются по мере работы.

## Структура

```
src/
  config.py       все гиперпараметры и сид
  paths.py        автоопределение среды (Kaggle / локально), пути к данным
  repro.py        сиды, фиксация потоков, md5, версии библиотек
  text.py         нормализация, лемматизация (pymorphy3) с кешем
  data.py         загрузка parquet, приведение id к строкам, ключ запроса, разбор фильтров
  validation.py   псевдо-бенчмарк из train, Recall@K
  bm25.py         BM25 и покрытие лемм на разреженных матрицах
  priors.py       P(микрокатегория | запрос), популярность и «память» по item_id
  candidates.py   пул кандидатов из нескольких генераторов + признаки пар
  tuning.py       линейная формула, подбор весов, итоговый топ-50
  submit.py       запись и строгая проверка answer.csv
notebooks/
  01_eda_baseline.ipynb   EDA → валидация → бейзлайн → answer.csv
tests/
  make_synthetic_data.py  синтетические данные в той же схеме (smoke-тест)
```

## Как запустить

**Локально**
```bash
pip install -r requirements.txt
# положить train.parquet, benchmark_queries.parquet, benchmark_items.parquet в ./data
# (или указать другую папку: export DATA_DIR=/path/to/data)
cd notebooks && jupyter nbconvert --to notebook --execute 01_eda_baseline.ipynb --output 01_executed.ipynb
```
Результат: `outputs/answer.csv`, отчёт и пулы — в `artifacts/`.

**Kaggle**: подключить датасет с данными (папка находится автоматически внутри
`/kaggle/input`), включить Internet, в первой ячейке указать `REPO_URL` / `REPO_REF`.
Для приватного репозитория добавить Kaggle Secret `GITHUB_TOKEN` (fine-grained токен
GitHub с правом Contents: Read-only на этот репозиторий); токен не попадает ни в вывод,
ни в `.git/config`. GPU для бейзлайна не нужен. Результат: `/kaggle/working/answer.csv`.

**Smoke-тест без настоящих данных**
```bash
python tests/make_synthetic_data.py --out data_synth
cd notebooks && DATA_DIR=../data_synth jupyter nbconvert --to notebook --execute 01_eda_baseline.ipynb --output smoke.ipynb
```

Переменные окружения `DATA_DIR`, `WORK_DIR`, `OUTPUT_DIR` переопределяют пути.
Сеть нужна только для установки пакетов; внешних API решение не вызывает.

## Подход (бейзлайн)

1. **Нормализация.** Все id — строки; «запрос» = нормализованный текст + локация +
   доставка + фильтры + категория поиска. Тексты лемматизируются (pymorphy3),
   стоп-слова удаляются.
2. **Пул кандидатов** (~1000 на запрос) — объединение списков:
   * топ-400 по тексту: BM25 по заголовку, параметрам и описанию + доля лемм запроса,
     найденных в заголовке/параметрах;
   * топ-400 по тексту с приоритетом объявлений своей локации;
   * топ-400 объявлений своей локации из самых вероятных микрокатегорий,
     P(микрокатегория | запрос) со сглаживанием
     «текст+категория → текст → отдельные леммы → категория → всё»;
   * объявления, выбранные в train по такому же мешку лемм (если объявления корпуса
     встречаются в train — решается автоматически по EDA).
3. **Отбор 50** — линейная формула над признаками пары (BM25 по полям, BM25 фильтров
   по параметрам, покрытие, log P(микрокатегория), совпадение локации, соответствие
   фильтру рейтинга, рейтинг, отзывы, популярность, «память»). Веса подбираются
   покоординатным перебором по сетке, максимизируя Recall@50 на валидации.

## Валидация

Псевдо-бенчмарк из train (детерминированное md5-разбиение):
* доля «знакомых» текстов запросов (встречающихся в train) подгоняется под бенчмарк;
  «новые» тексты убираются из train целиком;
* позитивы валидации подмешиваются в **реальный корпус бенчмарка**, чтобы
  распределение «чужих» объявлений было боевым;
* все статистики считаются только по train-фолду (без утечки);
* веса оцениваются честно: подбор на половине запросов, замер на другой.

## Воспроизводимость

* Единый сид (`CFG.seed = 42`), фиксированное число потоков BLAS (выставляется до импорта numpy).
* Нет итераций по `set` строк; дедупликация через `dict.fromkeys` / `np.unique`.
* Любой топ-K — по ключу (скор, округлённый до 1e-6, по убыванию; `item_id` по возрастанию),
  ничьих не бывает.
* Скор формулы считается поэлементно в фиксированном порядке (без BLAS).
* Разбиения — по md5, а не по встроенному `hash()`.
* Ноутбук печатает md5 итогового `answer.csv`. Проверено: md5 совпадает при разных
  `PYTHONHASHSEED` и в двух окружениях (pandas 2.2 / numpy 1.26 и pandas 3.0 / numpy 2.4).
